# AGENTS.md

Instructions for any coding agent working in `nxgt-zod`.

## What this repository is

A library monorepo in the nxgt skeleton (skill `lay-out-a-library-monorepo`;
nxgt-data is the reference): a Bun workspace whose `packages/*` go to npm under
`@nxgt/*`.

| package | what it is |
| --- | --- |
| `@nxgt/zod` | shared Zod 4 building blocks. First the scalar schemas: the exact validation rules `@nxgt/graphql-scalars` applies, so a REST app (code generated by `@nxgt/openapi-codegen` from a spec written with `@nxgt/typespec`) validates the same way without depending on `graphql`. Later an error map, user-friendly messages and i18n (`packages/zod/docs/roadmap.md`, Later) |

`@nxgt/zod` is **`"private": true`** until the owner approves the first
publish (skill §5). Removing it is a commit of its own. The release workflow
runs and publishes nothing meanwhile; `verify:artifacts` still packs and loads
the package, since `readPackages` includes private ones.

## Layout

```
packages/zod/
  src/index.ts                  re-exports ./scalars, for now
  src/scalars/index.ts          scalarSchemas, schemas, ScalarName, derived from all.ts
  src/scalars/all.ts            one line per category
  src/scalars/<category>/<name>.ts        one scalar per file
  src/scalars/<category>/<name>.spec.ts   its spec, beside it
  src/scalars/<category>/index.ts         one line per scalar
  src/scalars/registry.spec.ts            the guards below
  src/rules/                    helpers shared by several scalars
  test/schema-cases.ts          schemaCases, integerCases, refusal
  docs/guide/scalars/<category>.md        one page per category
```

Subpaths: `.` and `./scalars` (both in `exports` and `nxgt.entrypoints`).
`.` re-exports `./scalars` for now.

## Invariants

- **One scalar per file, by category, designed for 100+.** A file exports
  exactly two things: `<name>Schema` and `<name>Name`, the GraphQL name
  (`ibanName = 'IBAN'`). Nothing is listed by hand: `scalarSchemas` (keyed by
  the exact GraphQL name, code-unit order, `HSLA` before `HSL`) is built from
  the `*Name` exports, `schemas` (keyed by the export name without `Schema`)
  from the `*Schema` ones, and the types derive from `typeof all`.
  `registry.spec.ts` fails on a file not registered, without a spec, with an
  extra export, not named after its scalar, or without a `## \`<Name>\``
  section in its category's guide; and `scalar-schemas.spec.ts` fails when an
  entry widens to `z.ZodType`.
- **A new scalar** is a file, its spec, one line in its category's `index.ts`
  and a guide section. A new category is a folder, a line in `all.ts` and a page.
- **The rules come from `@nxgt/graphql-scalars`** (nxgt-graphql, `develop`,
  0.4.0) verbatim, comments included, without the GraphQL parts. A rule fixed
  there is fixed here and the other way round.
- **Messages are `Invalid <format>[: hint]`** and never name the value. Numbers
  keep Zod's own bound messages.
- **Codecs**: `dateTime` and `timestamp` decode to `Date`, `long` and `bigInt`
  to `bigint`.
- **Traps already paid for on the GraphQL side**: Node and Bun differ in
  `Intl` (`Locale`, `TimeZone`: Node rewrites the alias `Asia/Kolkata` to
  `Asia/Calcutta`, Bun keeps both), so those files hold the workarounds and the
  caches are built lazily; `Emoji` creates its `Intl.Segmenter` on first use,
  so a runtime without it fails `Emoji` alone; `z.iban()` checks neither the
  country nor the length, so `IBAN` adds the SWIFT registry table.
- **`zod` is a peer**, `>=4.6.5 <5`; `typescript` is a peer, `^6.0.3`. No
  `graphql` dependency, ever.
- **Imports carry no extension**; consumers resolve as a bundler does.

## The green bar

```sh
bun install
bun run check            # Biome
bun run build            # before typecheck: every `exports` points at dist/
bun run typecheck
bun run test             # under Bun
bun run verify:artifacts # packs, installs and imports every declared subpath
bun run changeset:status # on a branch cut from develop
```

## Releasing

Changesets. `bun changeset` describes a change; merging to `develop` opens a
"Version packages" PR, and merging that publishes. A change under `packages/`
needs a changeset (`bun changeset --empty` for one that reaches no consumer).
`scripts/publish.ts` skips private packages, so nothing goes out while
`@nxgt/zod` is private. `NPM_TOKEN` (a granular token covering the `@nxgt`
scope) is read through `bunfig.toml`, never `.npmrc`.
